Floppy v1.000 Base Engine Architecture

#
coreengineassets

The DOS floppy v1.000 release serves as the foundational source of truth for all modernizations.

What it does

Establishes Laura Bow II (Floppy v1.000) as the immutable base game directory. Loose patch files in the directory override compressed archive resources at runtime without corrupting original assets.

How it works

The SCI 1.1 interpreter loads resources using a two-tier lookup mechanism:

  1. The interpreter searches the current directory for loose resource files matching the naming scheme <resourceNumber>.<resourceExt> (e.g., 0.SCR, 13.MSG).
  2. If no loose override exists, the interpreter queries RESOURCE.MAP for the offset and reads from RESOURCE.000.
  3. Original uncompressed brushstroke background pictures and EGA/VGA palettes are preserved directly from the floppy media.

Why it works this way

The floppy release contains superior uncompressed brushstroke textures on backgrounds (such as the newsroom desk) and cleaner timing logic compared to the CD release. Building modular loose patches guarantees that original assets remain untouched and patches can be cleanly uninstalled or distributed.

Evidence
  • Game Version File LB2/VERSION
  • Resource Configuration LB2/RESOURCE.CFG
  • Resource Map LB2/RESOURCE.MAP

SCI Companion Execution Under Wine

#
toolingwinedecompiler

Win32 SCI Companion runs under Wine to decompile, edit, and recompile SCI 1.1 scripts and message resources.

What it does

Enables decompilation of compiled bytecodes (.SCR/.HEP) into human-readable SCI Studio / Sierra syntax (.sc), visual editing of message tables (.MSG), room priority boundaries (.PIC), and views (.V56) within Linux.

How it works

The developer launches SCI Companion via Wine using the pre-compiled binary:

  1. Execution command: wine /home/gordonk/PycharmProjects/SCICompanion/Release/SCICompanion.exe LB2/RESOURCE.MAP.
  2. Scripts are decompiled into source/ directories with symbol recovery driven by Decompiler.ini and selector vocabularies.
  3. Recompiled scripts emit paired .SCR (code chunk) and .HEP (heap object definitions) back into the game directory for immediate execution.

Why it works this way

SCI Companion provides high-level control-flow recovery (reconstructing while loops, if-else branches, and switch-cases) rather than raw assembly disassembly, dramatically reducing reverse-engineering overhead and preventing bytecode syntax bugs.

Evidence
  • SCI Companion Binary /home/gordonk/PycharmProjects/SCICompanion/Release/SCICompanion.exe
  • Decompiler Configuration SCICompanion/Files/Decompiler/Decompiler.ini

Modular SCI 1.1 Loose Patching Model

#
architecturebuilddistribution

Non-destructive drop-in patch architecture replacing only affected scripts and message lumps.

What it does

Compiles modified scripts and message lumps into individual standalone files in the LB2/ folder rather than repacking RESOURCE.000, enabling rapid iteration and isolated bug verification.

How it works

  1. Each bug fix targets specific script IDs (e.g., 0.SCR for global kernel logic, 13.SCR for interrogations, 440.SCR for Armor Room).
  2. The compiler emits <id>.SCR, <id>.HEP, and <id>.MSG.
  3. The ScummVM and DOSBox runtimes load loose files automatically in priority over RESOURCE.000 contents.

Why it works this way

Repacking RESOURCE.000 on every iteration risks whole-archive corruption, invalidates offset tables, and complicates git diff tracking. Loose patch distribution is the standard, verified Sierra patch methodology.

Evidence
  • Root Loose Scripts LB2/0.SCR
  • Message Loose Resource LB2/0.MSG

ScummVM Debugging and Test Automation

#
testingautomationdebugger

Automated regression testing, script inspection, and variable inspection using ScummVM.

What it does

Executes LB2 within ScummVM with debugger flags enabled, allowing live inspection of global variables, event queues, object properties, and scripted cutscene triggers.

How it works

  1. Launch command: scummvm -d 1 --auto-detect --path=LB2 sci:laurabow2.
  2. ScummVM debug console commands (Ctrl+Alt+D): var g, send ego, log, and sc to inspect script execution.
  3. Script regression tests are recorded with deterministic save states saved before key branches.

Why it works this way

ScummVM runs natively on Linux without emulation lag, reports detailed bytecode parse warnings and heap boundary violations, and enables headless scripting verification.

Evidence
  • ScummVM Detection Command scummvm --detect --path=LB2

Interrogating suspects across Act 2 requires dozens of questions. Requiring 5 clicks per question generates extreme player fatigue. Streamlining interaction keeps the mystery engaging while retaining full notebook depth.
